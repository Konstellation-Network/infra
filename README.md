# infra

Terraform + Ansible for the Konstellation validator fleet and supporting
infrastructure. Private, permanently (`ENGINEERING.md §6.4`) — this is a map
of where the validators live.

Structure follows `ENGINEERING.md §6.4`:

```
terraform/
├── modules/
│   ├── hetzner/{validator,sentry,rpc,archive,bastion,monitoring,cosigner}/   # hcloud
│   └── gcp/{validator,sentry,rpc,archive,bastion,monitoring,cosigner}/        # google
└── envs/testnet-1/                                 # instantiates both providers for one network
    ├── topology.tf                                 # the cross-cloud decisions, as locals
    ├── inventory.tpl.yml, ssh_config.tpl           # -> ansible/inventories/testnet-1/{hosts.yml,ssh_config}
    └── backend.tf                                  # partial gcs config — bucket NOT chosen (open)
ansible/
├── roles/
│   ├── {node,cosmovisor,horcrux,monitoring,firewall}/   # chain nodes (monitoring = node_exporter, every host)
│   ├── bastion/, wireguard/                        # jump hosts + the site-to-site tunnel
│   └── monitoring_server/                          # prometheus, alertmanager, grafana, tenderduty
├── inventories/testnet-1/                          # hosts.yml + ssh_config generated by terraform, see below
├── tests/                                          # render_test.yml + a fixture inventory: template regressions, no hosts
├── site.yml                                        # full fleet config, idempotent; bastions first
├── upgrade.yml                                     # stages a checksummed binary via cosmovisor (chain_nodes)
└── requirements.yml                                # ansible-galaxy collections (community.general, ansible.posix)
monitoring/
├── prometheus/alerts.yml                           # deployed verbatim by roles/monitoring_server
└── grafana/                                        # empty — see grafana/README.md
runbooks/                                           # on-call, emergency-halt, coordinated-upgrade,
                                                    # validator-key-rotation, validator-admission,
                                                    # incident-comms — none rehearsed yet
CODEOWNERS
```

`runbooks/` is written (2026-09-20) but every file says **Rehearsed: never**
at the top. The first halt drill (`ENGINEERING.md §13`, §15 Phase 5) is
where they get corrected — edit them in the same PR as the drill write-up.

## Current scope: testnet-1 only, split across Hetzner and GCP

**10 foundation-run validators, 5 per cloud** (`ENGINEERING.md` D7, re-decided
2026-09-20: the genesis set is 10 on both networks, all foundation-run, further
admissions permissioned via D16 — `runbooks/validator-admission.md`). Each cloud
has its own private network; they are joined by one routed site-to-site
WireGuard tunnel between the two bastions (see "Cross-cloud connectivity"):

| | Hetzner (`10.0.1.0/24`) | GCP (`10.0.2.0/24`) |
|---|---|---|
| Validators | 5 (`v1`-`v5`), no public IP, `.11-.15` | 5 (`v6`-`v10`), no public IP, `.16-.20` |
| Sentries | 5, 1:1 with their validator, public, `.21-.25` | 5, 1:1 with their validator, public, `.26-.30` |
| Archive | 1, internal only, `.41` | 1, internal only, `.42` |
| RPC | — | 1, public, `.31` |
| Bastion / gateway | 1, public, `.5` — SSH entry, **NAT egress** for the private hosts, tunnel endpoint | 1, public, `.5` — SSH entry, tunnel endpoint (egress is Cloud NAT) |
| Monitoring | — | 1, internal only, `.50` (`monitoring_cloud = "gcp"`, default) |
| Horcrux cosigners | `c1` fsn1, `c3` hel1 (`.61`, `.63`) | `c2` (`.62`) — only with `horcrux_mode = "dedicated"`; default is colocated, so none |

Each validator's sentry lives in the **same cloud** — the validator↔sentry
p2p link stays inside one private network and never crosses the tunnel.
Sentries from both clouds peer with each other over the public internet like
any other node. Only management traffic (SSH from a single-entry bastion,
metrics scrape, horcrux signing in dedicated mode) crosses the tunnel.

Host count with the defaults (`horcrux_mode = colocated`): 10 validators +
10 sentries + 2 archives + 1 RPC + 2 bastions + 1 monitoring = **26 hosts**;
`dedicated` adds 3 cosigners (29). `ENGINEERING.md §9.4` now says the same
fleet runs on both networks, so `terraform/envs/konstellation-1/` (not yet
created) should start as a copy of this environment with persistent disks
and `horcrux_mode = "dedicated"` (§18).

### Cross-cloud connectivity

Simplest safe default, chosen 2026-09-20 and **flagged for a human to
confirm**: one kernel-WireGuard tunnel between the two bastions, with a
cloud route on each side (`hcloud_network_route` / `google_compute_route`)
sending the other cloud's `/24` through its local bastion. Traffic is
routed, not NAT'd, so every firewall rule sees the real source IP and
"internal only" means `fleet_cidrs` (both `/24`s) rather than one subnet.
Why this and not the alternatives:

- *Public scrape with mTLS* needs a TLS proxy and a certificate on every
  node, and doesn't help horcrux at all. Rejected.
- *Managed interconnect / VPN gateways* — Hetzner has none. Rejected.
- *WireGuard on every node* is the same trust model with 15× the key
  material. Rejected.

Costs of the choice, stated plainly: the bastions are now routers (kernel
forwarding; sshd is still their only userland listener); the tunnel is a
single point of failure for cross-cloud *management* traffic
(validator↔sentry p2p never crosses it); and **in dedicated-horcrux mode
it is a single point of failure for consensus too** (adversarial review,
2026-09-21; STATUS §5a P22): the cosigners reach each other *through the
tunnel*, so a tunnel outage partitions the far cloud's cosigner from the
other two — and since each cluster's quorum path for the validators in
*that* cloud runs across the tunnel, 5 of the 10 validators stop signing
and the chain halts within seconds. `CloudUnreachable` says so. An
earlier version of this paragraph claimed "still quorate"; it was wrong.
**Design note (P22, not built):** the cosigners need their own
peer-pinned mesh — WireGuard between the three cosigner hosts over their
own public IPs (or redundant tunnels), pinned to each other's keys, so
that horcrux raft/grpc never depends on the bastions. Until that exists,
`dedicated` mode is a liveness downgrade, not only a key-safety upgrade;
testnet-1 runs `colocated`. WireGuard keys are generated on each bastion
by `ansible/roles/wireguard` and never leave it; only public keys travel,
as Ansible facts within one play, and each side refuses a fact that is not
a 32-byte base64 key before templating it into root's `wg0.conf`.

**Hetzner-specific:** hcloud firewalls filter the *public* interface only,
so hosts with no public IP are not covered by them at all — `ansible/roles/
firewall` (ufw) is the primary control on Hetzner, not a redundant one.
And a Hetzner server with no public IP has **no internet egress** unless
something NATs for it; the bastion does (`nat_gateway = true`, an
`hcloud_network_route 0.0.0.0/0`, and a cloud-init unit on every private-only
Hetzner host pointing its default route at the network gateway). Without
this the validators could never `apt-get` or fetch their checksummed
binary — a gap in the original scaffold, closed here.

### Cosigner admin domains (P21) — interim

One `deploy` SSH key with `NOPASSWD` sudo on every host was the original
scaffold, cosigners included: one leaked key = three shards = the consensus
key of all ten validators. **Interim (2026-09-21):** `var.cosigner_ssh_public_key`
is a separate key wired only into `modules/{hetzner,gcp}/cosigner`,
required in dedicated mode and validated to differ from `ssh_public_key`.
What it does **not** do — and what STATUS §5a P21 has to decide before
mainnet: the cosigner hosts still get the same `deploy` user with
unrestricted sudo (cloud-init), the three cosigners still share *one*
key, and the default `cosigner_placement` still puts two shards in one
Hetzner account (`fsn1` + `hel1`), so one hcloud API token can rescue-boot
a threshold — the plan prints `cosigner_placement_warning` for it.
Per-cosigner keys/operators, hardware-backed keys, restricted sudo and a
third provider are P21/P16, not this branch.

### Sentry topology (P23) — interim

One sentry per validator was the original scaffold. **Interim
(2026-09-21):** `ansible/roles/node/tasks/peers.yml` wires every validator
to *all* its cloud's sentries (5 today) and cross-peers every sentry with
every other on public IPs, with `private_peer_ids` = the same-cloud
validators; node ids are read after `init` so nothing is hand-copied. The
cloud firewalls and ufw admit p2p on validators from those sentries' /32s
only — the /24 used to include the internet-facing RPC node. Still P23: the
sentry *count* (≥ 2 per validator is the target; today the redundancy
comes from sharing the cloud's five) and a DoS on all five of a cloud's
sentry IPs still isolates that cloud's validators.

### Decisions parametrised here (defaults chosen, not decided)

All in `terraform/envs/testnet-1/variables.tf`, all documented inline:

| Variable | Default | The decision a human still owns |
|---|---|---|
| `bastion_ssh_entry` | `per-cloud` | one bastion reachable from both clouds vs one per cloud. Both bastion *hosts* exist either way (tunnel endpoints); this only picks which run an internet-facing sshd. `per-cloud` means a tunnel outage never locks you out of either side, which matters most in an emergency halt. `"hetzner"`/`"gcp"` gives a single audited entry point at the cost of that dependency — and is applied in two steps (first `per-cloud`, so ansible can reach both bastions to build the tunnel, then switch). |
| `monitoring_cloud` | `gcp` | where the one Prometheus/Grafana/Alertmanager/tenderduty box lives. GCP because Cloud NAT keeps its bastion out of the egress path. |
| `horcrux_mode` + `cosigner_placement` | `colocated` (no cosigner hosts) | testnet-1 keeps the original co-located mode; `dedicated` provisions 3 cosigner hosts (fsn1, us-central1-b, hel1 — no location or cloud holds two shards) and ansible runs one horcrux instance per validator on each. Mandatory for mainnet (§18). Switching a live validator is a key ceremony (`runbooks/validator-key-rotation.md`). |
| `backend.tf` bucket | **none** | the terraform state bucket. Still a partial `gcs` config; `terraform init -backend-config=backend.hcl` with a bucket a human creates. Not parametrised further because there is nothing to default to. |

**GCP validators use Local SSD, and that choice needs to be read, not just
trusted:** `terraform/modules/gcp/validator`'s `local_ssd_count` variable has
the full explanation, but the short version — GCP Local SSD doesn't survive
a stop or a host *error*. Scheduled maintenance is fine: per GCP's current
live-migration docs (checked 2026-09-21) VMs with Local SSD live-migrate
with the disk, so the module sets `on_host_maintenance = MIGRATE` (the
original scaffold had TERMINATE, which would have discarded the disk on
every maintenance event — **flagged for a human** to re-confirm against the
docs of the day before the first apply). For the host-error path, where the
VM auto-restarts with empty Local SSDs, `ansible/roles/cosmovisor`'s unit
carries `RequiresMountsFor` + `ConditionPathIsMountPoint` on the data
directory: the node stays down (a `NodeDown` page) rather than starting
with its key and a `priv_validator_state.json` at height 0 — the
double-sign scenario `ENGINEERING.md §2.7` calls unrecoverable (5% slash,
no undo). Local SSD was chosen for testnet-1 to match Hetzner's local-NVMe
performance profile on the other half of the fleet. `ansible/roles/node`
stripes the Local SSDs into one RAID0 array (a single 375 GiB disk doesn't
meet the multi-TB spec either way). **Re-decide this before any mainnet
validator runs on GCP**, probably in favor of `pd-ssd` despite its worse
commit latency; with dedicated Horcrux cosigners the key is no longer on
that disk, which is most of the risk.

## Known gaps — still open

- **Public RPC node exposes CometBFT RPC 26657 and REST 1317 to the
  internet** (`group_vars/rpc.yml`, `rpc_public` firewall) — unauthenticated,
  unmetered, a DoS surface. Acceptable for testnet-1 behind the
  `minimum-gas-prices` floor; put a rate-limiting reverse proxy in front
  (or move RPC to the app tier, `ENGINEERING.md §9.1`) before mainnet.

- **Terraform state backend** (`terraform/envs/testnet-1/backend.tf`) is a
  partial `gcs` config with no bucket chosen. **Human decision.**
- **`bastion_ssh_entry` / `monitoring_cloud` / `horcrux_mode`** have
  defaults, not decisions — table above. **Human decision**, before the
  first `apply` for the first two, before real validator keys for the third.
- **Version pins are empty.** `konstellationd_version`, `konstellationd_sha256`,
  `cosmovisor_sha256`, `horcrux_sha256`, `node_exporter_sha256`, and now
  `prometheus_sha256`, `alertmanager_sha256` are blank on purpose —
  `konstellation` hasn't cut a release build yet. Every download task
  asserts its checksum var is non-empty and fails closed.
- **tenderduty is unmaintained.** `github.com/blockpane/tenderduty` was
  archived on 2025-01-02; it ships as a container image only (no binaries),
  so `roles/monitoring_server` runs it under Debian's `docker.io` with a
  `latest` tag until a digest is chosen (`tenderduty_image_digest`,
  `tenderduty_require_digest`). Works today, will not get fixes. Evaluate a
  maintained fork before mainnet.
- **On-call rota** (`§17`): mechanics in `runbooks/on-call.md`, schedule
  TBD until validators exist. The alert routes stay placeholders until then.
- **GCP validator disk durability** — see the callout above. Not a gap so
  much as a decision deliberately deferred past testnet-1; with dedicated
  cosigners the key is no longer on that disk, which is most of the risk.
- **Metric names in `alerts.yml`** are CometBFT's documented convention, not
  yet confirmed against a live `/metrics` endpoint (see the caveat comment
  in that file). `promtool check rules` validates syntax, not names.
- **Grafana dashboards** — none (`monitoring/grafana/README.md`).
- **Not verified against real providers:** Hetzner's DHCP/route behaviour
  for private-only hosts (the cloud-init default-route unit and the
  WireGuard `ip route replace` lines are written to be harmless if DHCP
  already pushed the route — verify on first apply), Hetzner's private
  network handing out no resolvers (cloud-init writes `185.12.64.1/2`),
  GCP `can_ip_forward` + custom-route return paths through the tunnel, GCP
  live migration preserving Local SSD data on N2, and the exact Grafana apt
  package version.
- **Public RPC node `minimum-gas-prices`** (`group_vars/rpc.yml`): a
  node-local 1 gwei-equivalent floor so the one internet-facing mempool is
  not a free spam target. Not a protocol parameter (TOKENOMICS.md §3 keeps
  that at 0), but it does set what users of the public RPC pay at minimum —
  **flagged for the TOKENOMICS owner** to confirm or lower.
- **Explorer reachability** (found by the explorer's live run, 2026-09-20):
  archive nodes now bind JSON-RPC/WS to their private address instead of
  init's `127.0.0.1` (`group_vars/archive.yml` `jsonrpc_bind_address`), and
  `var.explorer_cidrs` / `archive_rpc_allowed_cidrs` gate who may reach
  them — both empty/fleet-wide until the explorer host exists and its
  route into a private network (a bastion WireGuard peer, or a host inside
  one cloud) is decided. **Open**: that route.
- **IPv6** is only opened on the Hetzner sentry firewall, not GCP's
  (would need a dual-stack VPC there) — a minor asymmetry, not a security gap.

## Apply flow (once the open gaps above are closed)

```bash
cd terraform/envs/testnet-1
cp terraform.tfvars.example terraform.tfvars   # fill in, do not commit
gcloud auth application-default login           # or set GOOGLE_APPLICATION_CREDENTIALS
terraform init -backend-config=backend.hcl      # backend.hcl gitignored, not yet written
terraform plan
terraform apply
# writes ansible/inventories/testnet-1/hosts.yml and ssh_config from outputs

cd ../../../ansible
ansible-galaxy collection install -r requirements.yml
ansible-playbook site.yml --limit bastions            # first: everything else is reached through them,
                                                      # and Hetzner's private hosts have no egress until NAT is up
ansible-playbook site.yml --limit validators --check  # dry run one group first
ansible-playbook site.yml
```

Humans: `ssh -F ansible/inventories/testnet-1/ssh_config testnet-1-gcp-validator-v6`.
Dashboards: `ssh -F … -L 3000:localhost:3000 -L 9093:localhost:9093 -L 8888:localhost:8888 testnet-1-gcp-monitoring-1`
then Grafana on :3000, Alertmanager :9093, tenderduty :8888.

Fleet upgrades: `ansible-playbook -i inventories/testnet-1/hosts.yml upgrade.yml -e upgrade_name=... -e binary_sha256=... -e binary_url=...` (`ENGINEERING.md §16`, `runbooks/coordinated-upgrade.md`). One invocation covers both clouds — `upgrade.yml` targets `chain_nodes`.
